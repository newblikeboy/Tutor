# Parent discovery and booking

The 2026-10-09 operator direction supersedes the former learning-needs / mentor-reviewed trial / tutor-accepted regular booking flow.

1. Parent adds a learner using the existing private profile and guardian controls. The finder uses the saved class, board and teaching language. No additional learning goal or requirement record is created by this journey.
2. Parent opens the finder from the Home page Find a tutor button, carrying the selected learner. There is no duplicate Find a tutor entry in the desktop sidebar or mobile menu. Parent selects learner, Online or Home Tuition, subjects and a distance radius, then searches. Home distance uses the parent account location and the tutor's service location/radius. Online search does not filter by physical distance. Selections and search state survive reload through the URL. Existing database-backed cards and availability calendars remain.
3. Classes 1-5 offer exactly **All Subjects**. Classes 6-12 permit multiple standard teaching subjects. A tutor must have staff-approved coverage for every selected subject, class and teaching mode; requested subjects alone never grant approval. Staff can approve complete requested areas across Classes 1-12, with All Subjects limited to Classes 1-5.
4. Parent requests a trial directly for the learner. Trial acceptance by the tutor remains. Tutor submits lesson notes, practice steps and feedback together; the parent sees them immediately on completion. There is no mentor review action. Production still requires the trial to have ended before completion.
5. Parent chooses that tutor's staff-confirmed Online hourly or Home weekly/monthly package, approved subjects and an available start date **tomorrow or later** in the schedule timezone. Weekly Home packages include **6 classes** and monthly packages **24 classes**. These are class-count packages: dates may span multiple weeks or months. Staff set package prices and class duration. The immutable agreement stores selected subjects, base package price, total and staff/availability versions. For Classes 1-5 the total is one package fee; for older learners it is package fee multiplied by selected subject count.
6. Booking atomically reserves tutor/learner slots with a 15-minute hold and enters `awaiting_payment`. Parents see **Complete your booking** with the selected classes, dates and total, plus a **Continue to payment** link when returning to the list. Unpaid/expired selections do not appear as regular booking cards; class counts and workspace tabs appear after activation. The checkout refreshes the server status automatically and an expired hold asks the parent to choose new dates. It does not require tutor acceptance. A verified provider capture rechecks scope and availability, promotes held classes to scheduled and activates tuition. A client callback alone never activates tuition; expiry/late capture/refund handling remains explicit. Zero-price sample offerings cannot bypass payment.
7. The Learners menu opens the child progress report: learner/date/subject/tutor filters, Overview, Subjects, Class history and Feedback. It combines authorised records across packages and tutor changes; Add learner and Edit profile remain secondary actions. Tutor-recorded topic evidence, homework status and optional test marks appear immediately. See `learner-progress.md`. For regular lessons, present attendance plus tutor notes completes the class directly. Absent attendance is missed; a real attendance dispute retains assigned-mentor resolution. Earnings still require actual class end, verified capture and finance tax assessment; future development recordings do not release earnings.

The package picker schedules the full class count at the selected time on matching teaching days, skipping planned leave without reducing the included classes. It shows every date before consent and continuing. There is no calendar-week or calendar-month deadline. The existing six-month scheduling horizon and server scope, conflict, price-version and payment checks remain authoritative. Home-only offerings expose their staff fee version just like Online offerings. New published Home offerings use 6/24 classes without rewriting stored historical fee plans or existing agreements.

Historical requirement/draft records, reviewed trials/classes, single-subject scopes and pending agreements remain readable and use explicit compatibility paths. Existing agreements retain saved prices. No historical data migration widens tutor scope or rewrites feedback. New interfaces no longer offer learning-needs creation or academic sign-off.

Production guardian verification and payment release remain gated. Local database payment tests use a test-only gateway adapter; no real charge, delivery or deployment is performed.
