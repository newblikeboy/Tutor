# Implemented access boundary

| Actor | Permitted in development/test | Denied |
|---|---|---|
| Anonymous | Read approved public tutor DTOs; email/password signup as an adult parent/tutor; sign in | Staff registration, academic approval, private learner/application/lesson records |
| Parent / adult learner | Own learners/consents/requirements/trials; agreements/classes/plans/handover consent; current conversation/files; own billing/refund requests; own service/privacy/safeguarding requests | Other households; self-granted staff roles; academic approval; provider/refund approval |
| Tutor | Own application/documents/availability; scoped trial and agreement acceptance; assigned classes/lesson evidence/conversation/files; replacement acceptance | Self-approval; all-learner browsing; unrelated tuition; access after handover or enrollment closure; finance operations |
| Mentor | Read submitted applications; claim review with conflict declaration; schedule interviews, assess and approve assigned applications; assigned tuition learning plans, attendance review and handover preparation | Self-assessment; changes to another assessor's records; suspension/termination; unrelated family learning records; finance and other people's safeguarding data |
| Admin | Application queues/details/files/history; assign reviewers; personally claim, interview and assess applicants; approve own assessments with an ongoing academic mentor; reasoned suspension/reinstatement/termination and follow-up outcomes; eligible service/safeguarding decisions; finance reconciliation and independent refund review | Approval without an assigned completed assessment; self-assessment; unrelated family learning data/files; unclaimed case contents; approving own refund request |
| Support | Own requests plus eligible non-safeguarding queue; claim then respond/wait/resolve | Academic dashboards/learning files; finance operations; another person's safeguarding data; other operators' case contents |
| Finance | Payment/refund/journal records, payment jobs and reconciliation; independent refund review; own service requests | Academic dashboards/learning files; another person's service/safeguarding contents; self-approved refunds |

All production authenticated operations currently return 503 until recovery/security/MFA/guardian gates are reviewed. Staff login accepts provisioned email/password credentials; there is no staff role selector or public staff signup. A role/version update invalidates earlier sessions. Login rotation/logout revoke prior sessions and clear private TanStack Query state. Expiry is checked independently of TTL cleanup. Legacy OTP sessions cannot authenticate after the password migration.

All authenticated adults can update their own name/language, change a password after current-password verification and revoke their own other sessions. Notification access is owner-only. The CLI creates staff accounts under an explicit operator identity/reason and never changes an existing public account's role. It does not implement invitations, staff MFA or a permission-management UI.

Known limits: staff academic scope is presently online Mathematics (classes 6–10). General reviewer conflict declarations are enforced; specialist authorization, granular invites, privacy execution and safeguarding protective-action/escalation workflows remain open. A submitted case is an actual persisted request, not proof of legal compliance or completed deletion. Tutor metadata for ended trials is retained with learner name/notes/review redacted; operator retention review is required. The `/workspace` page sends finance/support to their functional work areas (`/billing`, `/cases`); the academic dashboard API continues to deny these roles.

The September 23 staff feature request authorizes provisioned administrators to conduct assessments. Every approval still requires assignment, a conflict declaration, a started interview, six scores, written evidence, a bounded scope and a provisioned academic mentor for ongoing tuition. It does not grant public role promotion. Suspended/terminated tutors lose active sessions and teaching-route access, but can sign back in for their own decision, account and support. Termination has no reinstatement route. See [staff operations](staff-operations.md).
