## Layout specifications for the most important screens

**Parent Home, returning learner:** Header and learner selector → next activity with date/mode/tutor and exact lesson action → small valid-checkout notice when relevant → Find a tutor panel → latest recorded feedback/next practice → View progress. For first use, Add learner takes precedence. On mobile, one column and short card summaries; do not render a grid of empty metrics.

**Learner report:** Learner identity and Edit profile → four existing tabs → compact summary in Overview → recorded next practice/feedback → package balance → links to detail. Desktop filters can remain visible; mobile opens a filter disclosure showing active count. The subject/history/feedback tabs contain the complete evidence; Overview does not replace them.

**Booking:** Persistent learner/tutor/subjects identity → selected package with class count and per-subject explanation → available start/date/time → schedule review including final class date → saved terms and actual payable total → Pay. Preserve entered selection through visible errors. A change in staff price/version forces quote reacceptance.

**Tutor lesson:** Selected learner, subject, date/time and status → approved preparation/join controls → brief and planned subject → attendance/progress task when due → saved observations/history and permitted correction action. Cancellation/dispute actions are visibly distinct from ordinary teaching actions.

**Staff decision:** Entity summary → relevant evidence and current state → required decision/reason controls → explicit confirmation for consequential status actions → actual server result and history link. Do not trade fewer clicks for weaker approval/accountability.

## Required state matrix

Implementation must cover first use, populated records, no match, filtered empty, loading, recoverable outage, denied/expired access, stale version/scope, validation errors, saved success and history. Booking additionally needs provider disabled, rejected payment, verification delay, expired hold and already-confirmed retry. Tutor work additionally needs paused/leave/conflict, absent attendance, missing evidence, correction deadline and handover revocation.

Not every state was exercised in this audit. Add targeted isolated browser/API checks when the corresponding screen is implemented, and document unavailable live-provider checks honestly.
