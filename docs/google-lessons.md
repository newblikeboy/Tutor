# Google Meet teaching lessons

The operator's 2026-10-11 request removes Zoom integration and selects Google Meet for interviews and teaching lessons. `MEETING_PROVIDER=google` enables regular online classes and confirmed online trials; `INTERVIEW_PROVIDER=google` enables interviews. Both settings also accept `disabled`. Zoom credentials, adapter, worker dispatch and meeting controls have been removed.

Use the same private Google OAuth settings and persistent encryption key described in [Google setup](google-interviews.md). An approved tutor connects their own Google account from Home; Google connection and failed cancellation recovery remain reachable under Account → Sign-ins when teaching access is paused. Interview applicants do not need Google authorization simply to join their mentor's interview.

Only the assigned approved tutor can prepare a lesson. Each creation uses a deterministic Calendar event ID and conference request ID, a durable leased outbox job and encrypted organizer authorization. The primary Calendar supplies the Meet conference. Calendar notices go to the parent's validated account email; learner names, authored progress and private addresses are omitted. Existing scope, payment, enrollment, guardian, assignment, class-version and CSRF checks remain. Home Tuition has no online meeting controls.

Mentor interviews and teaching lessons contend on the connected Google account's calendar guard. Distinct Google accounts can host independently; shared accounts cannot double-book. The adapter additionally checks Calendar events before creation. A successful provider response followed by a failed database write reconciles the same event rather than creating a duplicate. Pending conferences poll with a bounded confirmation window and explicit failures.

Parents and tutors obtain a join link only through the lesson API after current assignment/scope and the 15-minute join window pass. The API verifies the current Google event, Meet URL and lesson times before issuing it. Public lesson records omit provider event IDs, OAuth credentials and reusable organizer information. Cancellation, completion, rescheduling and handover remove operational join access and queue conditional Calendar deletion. Cancellation arriving during creation skips an obsolete create or queues cleanup of the resulting orphan event.

Calendar changes are never silently overwritten. A failed conditional deletion appears in the tutor's Google connection card. The owning tutor reviews the current event and explicitly confirms its ETag before retrying deletion. Another edit requires another review. If the event has since disappeared, explicit confirmation rechecks its absence and closes the retained cleanup without deleting anything. Creation conflicts require cancellation/rescheduling through the lesson controls. Disconnect and switching Google accounts are blocked while hosted meetings or unresolved provider jobs need the authorization; reconnecting the same account remains available for cleanup after teaching access is paused.

Historical Zoom records and audit keys remain readable as history. Preparing Google Meet for an existing lesson archives its old meeting metadata in `meetingHistory`. No old Zoom job is dispatched, and no old invitation is automatically converted or cancelled at the external provider. The operator must manage any existing external Zoom invitation separately. Old interview bookings can be closed locally before scheduling Google Meet; they cannot satisfy a new approval or expose a Zoom join button.

`go run ./cmd/migrate --google-only` is repeatable and adds organizer/status indexes for classes, trials and the outbox without rewriting retained records. No production deployment or real Google invitation was performed. Live consent, redirect registration and Google account eligibility still require operator verification. The existing saved production callback is preserved; local live OAuth needs the registered local callback and process override described in the setup document.

Tests use isolated MongoDB replica-set databases and loopback Google/SMTP fixtures. Teaching regression covers legacy metadata preservation, ownership/assignment denial, shared-calendar conflict, uncertain creation without duplicates, cancellation during creation, current join authorization, completion cleanup, external ETag edits and explicit owning-tutor recovery. Browser flows verify tutor connection and Google Meet preparation/join alongside the interview/approval and teaching workflows.
