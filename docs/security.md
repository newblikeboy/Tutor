# Security checkpoint

Implemented: email/password signup/login, Argon2id with independent random 16-byte salts (19 MiB, 2 iterations, 1 lane, 32-byte key), 15–128-character passphrases, a small common-password rejection list, bounded hash concurrency, persistent per-email/IP rate limits, generic credential errors, normalized unique email credentials and atomic signup. Opaque random session tokens are hashed at rest; cookies are HttpOnly/SameSite, with explicit expiry, privilege-version revocation, login rotation/logout revocation, exact Origin and session-bound CSRF checks. JSON decoding rejects unknown fields and multiple objects: 16 KiB normally, 64 KiB for learning plans and a bounded 4 MiB base64 file envelope. Public signup cannot create staff or approve tutors. Seeds remain blocked in production. Explicit password configuration enables non-sample public and provisioned staff accounts under the operator password-only override, with Secure cookies and distinct production sessions; see production-auth.md.

Account operations persist name/language preferences, expose only the current user's active session references and allow explicit session revocation. Password change verifies the current password, performs bounded Argon2 work outside the transaction, compares the existing credential hash, increments the user's authentication version, removes all sessions and creates a fresh current session atomically. Login rechecks the credential inside its transaction to prevent a concurrent password change from being bypassed. Staff bootstrap uses hidden terminal input or an explicitly selected secret-manager pipe; it creates new audited accounts only and cannot overwrite or promote an existing account.

Tuition access is role plus ownership/assignment scoped. Family-consented handover changes the current tutor under the same enrollment locks used for messages/files, preserving family records and revoking the previous tutor's access. Finance cannot browse academic records; support cannot browse another person's safeguarding evidence. Service case details are redacted before eligible independent operator assignment. Safeguarding staffing/protective actions remain incomplete; the case inbox does not imply external escalation or emergency service.

Private uploads validate size/signature, image decoding and filenames; enforce per-user quota; use opaque private storage keys; and start quarantined. Only a successful configured ClamAV scan permits downloads. Download requests verify current assignment, file integrity and assignment again after storage I/O, with no public bearer URL. Actual object-storage and scanner deployment, retention, deletion and restore still require review. See [private-files.md](private-files.md).

Payment orders use server-calculated integer INR and saved agreement ownership. Checkout callbacks require exact HMAC verification and provider lookup; webhook signatures cover raw bounded bytes before parsing. Unique receipts, provider IDs, leased jobs and transactional journals handle duplicate/out-of-order events. A late or unusable captured payment creates refund review instead of restoring an expired booking. Refund approval requires a different eligible reviewer. External calls never run inside retryable MongoDB transactions. Test seams are restricted to tests; live integration remains closed. See [payments.md](payments.md).

OTP endpoints and code display were removed at the user's request. Old OTP sessions are rejected; legacy challenge records expire under their existing TTL. Emails are not verified by password signup. No guardian identity, SMS delivery, real assessment or payment is asserted by fixtures. Screenshots capture empty account forms or fictional records; never capture entered passwords. Do not enter real child information in the preview. Optional seed credentials require a private `SEED_PASSWORD`, are limited to development/test, and do not overwrite existing hashes.

The root `.env` is ignored and was not copied into source, the contract, the browser build or docs. The user-created `,env` filename was corrected to `.env`. Never print the URI. Error logs now record only Go error types and request IDs, not MongoDB connection error strings. Review logs before sharing them.

Known limitations: email ownership/recovery delivery, full breached-password screening, staff invitations, actual S3/ClamAV verification, safeguarding protective actions, audit retention/privacy erasure, independent security review remain launch blockers. The password denylist is deliberately small and is not presented as a breach check. Collection validation currently enforces required fields; richer schemas are pending. Production config requires loopback API binding. Per-client throttling trusts only one parsed IP from the loopback proxy; Nginx must overwrite X-Forwarded-For with $remote_addr. Untrusted peers and address chains cannot override the socket peer.

Password parameters and API were checked against [OWASP password storage guidance](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) and the [Go Argon2 package](https://pkg.go.dev/golang.org/x/crypto/argon2). Existing pinned `golang.org/x/crypto v0.53.0` is now a direct dependency; no framework or application backend was added.

Test fixtures live in newly created `tutor_test_*` and `tutor_e2e_*` databases. Tests do not delete existing data. The operator may explicitly approve removing only those generated databases after review; never infer a cleanup target from arbitrary URI text.
