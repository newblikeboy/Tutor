# Architecture and current boundary

React 19, strict TypeScript, React Router and Vite call a same-origin `/api/v1` Go/chi API. TanStack Query owns server state, React Hook Form/Zod validate application/login forms, and react-i18next provides English/Hindi UI. Tailwind v4 and custom tokens style reusable accessible components; Radix handles dialogs and drawers. Frontend types are generated from `contracts/openapi.yaml`.

Go is the only application backend. Packages: `config` (fail-closed startup and literal development `.env` loading), `domain` (models/invariants), `storage` (official MongoDB driver v2, repositories, migrations/fixtures), `app` (HTTP, auth, workflow transactions, schedule guards and leased jobs), `password`, `payments` (Razorpay HTTPS), `media` (private disk/S3 and ClamAV) and `staff` (audited CLI provisioning). This remains a modular monolith; the API owns its background worker.

Recruitment now adds authenticated Cloudinary videos in `media` and Zoom S2S OAuth in `meetings`. Application attachments use bounded embedded metadata; bytes remain in private object storage. Zoom operations use the existing durable outbox, protect the shared host's schedule and reconcile ambiguous creates without issuing duplicate create requests. New tutors stay in the application flow until server-approved, unexpired scope unlocks teaching APIs. See [recruitment integrations](recruitment-integrations.md) for configuration, failure behavior and live-provider limits.

MongoDB Atlas is configured privately in the root `.env`; it is never available to Vite. The supplied connection was verified and migration/seed commands succeeded against `tutor_dev`. Integration and E2E tools create separately named databases on that same cluster. They retain their own test records for review and do not drop or overwrite existing databases. See progress for executed evidence. Tests can alternatively use a real local WiredTiger replica set via optional `npm run db:local`; it downloads a MongoDB binary and persists to `.local/mongo`. No Docker is required or included.

Public parent/tutor signup requires email OTP before account creation. The request persists only a pending email challenge and encrypted code outbox job; confirmation consumes the same-email, current, unexpired code and creates the verified adult user, credential, session and audit in one transaction. SMTP code delivery uses the dedicated post-commit worker, with resend/guess/IP/address/hour limits and uncertain-delivery safeguards. Email-code login and recovery also remain available; provisioned staff use passwords only. The `password` package uses salted Argon2id (19 MiB, 2 iterations, 1 lane), separate normalized unique credentials and bounded password work. Login errors do not distinguish unknown email from wrong password. Opaque HttpOnly/SameSite=Lax session cookies have hashed tokens, explicit expiry, rotation and revocation. Secure production sessions use distinct password/email methods; legacy and development sessions cannot be replayed. Email verification does not establish guardian status, academic approval or payment. The production API binds loopback and trusts only a single client IP overwritten by Nginx. See `production-auth.md` and `email.md` for configuration and live-provider limits.

The initial journey remains an online, zero-fee **development trial**. Reviewed trials can now continue into immutable tuition agreements, recurring classes, versioned learning plans and family-consented handover. Fees are integer paise from the current tutor offering and frozen into each agreement; later fee changes never rewrite accepted history. Terms are explicitly development drafts awaiting operator review.

Trial acceptance and confirmation are a single transaction in the zero-fee path. It writes the tutor application version, serializing against approval/suspension changes, and authoritative tutor/day plus learner/day guard records. Each guard has bounded intervals; writers contend on its version. Both UTC dates are locked across midnight. Cancellation removes reservations under the same locks. Guard initialization is idempotent before the transaction. MongoDB transaction callbacks run sequentially and make no external calls. A unique actor/idempotency-key record stores a body fingerprint and original result. The conflict test sends concurrent HTTP requests to separate API instances with separate database clients.

Ongoing scheduling shares the trial guard protocol. Tutor and learner UTC-day interval locks enforce weekly IANA-time-zone availability, exceptions, buffers and capacity. Recurrence rejects ambiguous/nonexistent wall times. Paid acceptance creates explicit expiring holds; verified capture rechecks scope/availability and promotes the reservations atomically. Expired or unusable captures create a financial record and operator review. Recurring conflict rolls back the full attempted series. Suspension creates a persisted operator task without silently deleting paid sessions.

Conversations are shared between the family/current tutor/assigned mentor. Owner-only notifications carry generic references. Service cases use claim-before-disclosure and separate safeguarding permissions. Files store metadata in MongoDB and bytes in private storage; they stay quarantined until an actual configured scan succeeds. Assignment is checked on every access, including after storage reads. New list endpoints use bounded cursor pages; legacy dashboards and some histories still cap at 100 and require further pagination.

Billing uses a real Razorpay adapter only when private test configuration is present. Raw signed webhooks save deduplicated reference-only events; outbox jobs use durable leases, backoff, bounded attempts and explicit finance retry. No external effects occur inside MongoDB transaction callbacks. Captures/refunds write balanced immutable journal entries; these are not tutor earnings or bank settlement records. Commission allocation, tax invoices, disputes and approved payouts remain unimplemented. No actual provider request was sent during verification.

The current extension was exercised on an actual local WiredTiger replica set after Atlas reached its collection limit. The configured application still points to Atlas; there is no automatic fallback or completed Atlas migration claim. Read-only diagnostics created an exact proposed retained-test cleanup manifest. No database deletion has been authorised/performed. See the current [progress](progress.md) and [acceptance matrix](acceptance-matrix.md) for implementation limits and test evidence.

Deployment: GitHub source/CI → build artifact → DigitalOcean droplet. Nginx serves static React files and proxies API requests to a loopback Go service managed by systemd. Atlas remains external. Node is unnecessary in the running application if artifacts are built in CI. No public deployment was performed. Public tutor pages currently use client rendering; marketing pre-rendering and dynamic SEO work remain open.
