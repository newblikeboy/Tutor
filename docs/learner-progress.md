# Private learner progress reports

The Learners menu opens a report for the selected child. Home remains the tutor-discovery entry. Add learner remains in the workspace heading and Edit profile is a small report action. Learner selection, the Overview / Subjects / Class history / Feedback tab, report period, subject and tutor filters use URL state. Changing learner clears subject/tutor filters. Dates use Asia/Kolkata, including month boundaries; report periods never constrain package scheduling.

## Report data

`GET /api/v1/learners/{id}/progress` is available only to the owning parent. It returns the complete owned learning history without the generic list helper's 100-record limit: active/paused/completed enrollments, retained paid or taught cancelled arrangements, non-held class records, completed trial feedback, immutable learning-plan versions and accepted handovers. Pending, expired and unconfirmed cancelled checkouts are excluded. Names are projected from only the records' authors; old class tutor attribution survives a handover. Existing single-subject agreements remain readable. Shared multi-subject records are labelled without inventing per-subject results.

Overview shows completed classes, attendance from present/absent marks (disputes and unmarked classes excluded), checked homework, recorded tests, latest completed-class/trial feedback, next practice, current package balance and the learning journey. Package counts cover all saved package dates independently of the report period. Topic states and supporting observations appear in Subjects, with test marks and a chronological score comparison. Class history uses expandable lessons; Feedback includes tutor notes and trial feedback. Saved learning plans and explicitly labelled historical reviews remain readable. No score or homework completion is inferred from attendance or notes.

## Tutor progress recording

An assigned, currently approved tutor must include structured progress when recording a present-attendance lesson. The tutor can correct progress for their own completed class for seven days after recording, including when the package is completed; historical classes without a recording timestamp use their end time. Completed packages stay closed to scheduling, files and messages. See `docs/tutor-workspace.md`. Fields: booked lesson subject (individual subject detail is allowed within a Class 1-5 All Subjects agreement), 1-10 topics with status, observation and practice, homework status, feedback, next steps and an optional named test with integer marks. Topic statuses are Introduced, Practising, Independent and Needs attention. Homework is Not checked, Assigned, Completed or Needs help. Test maximum is 1-10,000; marks are 0 through that maximum. Dates are stamped on the server.

The existing class-action API uses `action: progress` and a version check. Transactions serialize progress writes with assignment changes, cancellation and approval restrictions. Former tutors and other households cannot edit. Progress-only edits preserve attendance, notes, package state and all financial entries. Recording a new lesson retains the production end-time requirement; development timing is explicitly labelled. Feedback appears immediately without mentor approval. Staff learning plans remain a separate existing workflow.

Progress is stored as an optional bounded `progress` document on the class; historical classes require no migration. OpenAPI authoring and generated types include the owner-only report and progress inputs. Private query caches clear on logout, and Refresh workspace refreshes the report. No learner information is stored in localStorage.

## Acceptance evidence

Real local MongoDB tests cover complete 125-class history, another parent's denial, role and assignment boundaries, old-tutor revocation, saved marks, invalid marks/subjects, version conflicts, server timestamps, cancelled checkout exclusion and financial/package-state preservation. Frontend tests cover India date boundaries, attendance denominators, checked homework, zero marks, latest subject observations and month-independent package balances. The persisted browser flow covers all report tabs at 1440/390px, learner/subject/tutor/date filters, reload, keyboard navigation, tutor progress recording and editing, validation and error recovery. Fictional recorded-history fixtures are confined to the exact isolated test database; they do not claim real payment activation or attendance. Booking/payment acceptance is covered separately.
